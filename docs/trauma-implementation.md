# AI 결과 제안과 엔진 확정 — 2026-09-25

## 실제 원인과 변경

기존 전투는 엔진의 난수와 도구 위력으로 피해량·부위를 정하고 `body.injury`와 간단한 `wounds` 이력만 남겼습니다. 출혈·통증·시야·이동 기능의 별도 지속 상태가 없어 서술을 길게 해도 이후 행동에 같은 제약이 이어질 수 없었습니다.

실행 중인 실제 API 세계에서는 공격 완료 시각에 시계를 멈추고, 가능한 ATTACK/ROB를 같은 시점 최대 8개씩 묶어 AI에 판정을 요청합니다. 요청 크기 제한을 넘으면 배치를 줄입니다. 부상마다 별도 호출하지 않습니다. 기존 예산 예약·사용량 계산을 사용합니다. AI가 제출하는 것은 명중 여부와 공통 부상 구조이며, 관리자에게 부상 사례를 입력받지 않습니다.

엔진은 준비된 도구·겨냥 부위·상대가 선택한 대응을 먼저 확인합니다. AI는 이를 변경하거나 물건·발언·이동·사망을 만들 수 없습니다. 전체 배치의 ID·중복·스냅샷·대응·상처 호환성을 검사하고 모두 통과한 뒤 결과를 보존합니다. 이미 승인한 응답은 지속 저장되므로 해당 응답을 재판정하지 않고 완료할 수 있습니다. 승인 전 오류는 행동을 보존하고 일시정지합니다. 관리자의 **재개**로 재시도할 수 있습니다.

## 공통 상태와 기록

- 부위: HEAD / TORSO / ARM / LEG
- 상처 유형: abrasion / laceration / contusion / fracture
- 세부 위치: general / scalp / face / eye
- 심각도, 출혈, 통증, 회복 시간
- 기능: vision / mobility / dexterity / attention
- 기능 저하 원인: pain / blood_obstruction / structural
- 원인 사건 ID, 발생 시각, 처치 시각, 회복 여부
- 누적 출혈 부담, 현재 통증, 현재 기능 제약

EVENT LOG에는 검증된 AI 제안과 모델·스냅샷 지문, 엔진의 준비·공격·대응·결과, trauma 전후 값이 함께 남습니다. AI의 자유문장 판정 이유는 감사용으로 보존하지만 검증된 사건 사실로 서술기에 전달하지 않습니다.

시간 경과는 API 없이 분 단위로 적분합니다. 출혈 지속·응고·처치·회복을 갱신하며, 의미 있는 상태 등급 변화와 사망만 공개 사건으로 발행합니다. 사망은 실제 누적 상태로 엔진이 확정하고 진행 중 행동을 취소합니다. 세계 종료 규칙이 충족되면 이후 틱도 정지합니다. 경미한 출혈은 즉시 사망으로 이어지지 않습니다.

이동·탐색 시간에는 이동 제약이, 공격 가능성과 기대 비용에는 시야·손 기능·통증이 반영됩니다. 현재 부상은 본인의 지식 입력에 전달되고 치료·도움 요청 후보가 생깁니다. 다른 인물의 비공개 임상 정보는 행동 판단용 지식에 공개하지 않습니다. 처치에는 실제 의약품이 필요하고 수량이 감소합니다. 처치 완료가 즉시 완치로 처리되지 않습니다.

기존 데이터에는 trauma가 선택 필드로 추가됩니다. 새 확정 부상부터 생성하며, 과거의 단순 부상 수치에서 출혈·부위 등을 추정해 소급 생성하지 않습니다. 과거 기록이나 챕터를 삭제·덮어쓰지 않습니다. DB의 기존 JSON 상태 저장 구조를 유지합니다.

## 실제 검증

전체 단위·통합 테스트 159개, PC·모바일 LIVE/DAY 및 부상 표시 E2E 8개 통과. 타입 검사·프로덕션 빌드·번들 비밀정보 검사 통과.

새 테스트는 다음을 확인합니다: 미확정 공격의 시간 정지, 부상과 이벤트·지식의 일치, 직렬화 보존, 같은 사건의 부상 중복 적용 방지, 존재하던 돌이 바뀐 스냅샷 거부, 빗나감+부상 거부, 방어 선택 변경 거부, 과도한 경미 출혈 거부, 이동 시간 증가, 시야에 따른 공격 확률 감소, 의약품 소비, 즉시 완치 방지, 다음 DAY 회복, 심한 지속 출혈 사망, 세계 종료 후 정지, 동시 공격 한 요청, API 실패 무피해·재시도.

### 실제 API 응답

격리된 세계에서 gpt-4.1-mini 1회 전투 판정 + 서술·검토 각 1회, 총 6,825 토큰을 사용했습니다. 결과는 **BLOCKED / injury:null**이었습니다. 부상을 얻기 위해 같은 요청을 반복하지 않았습니다. 상태에도 부상을 추가하지 않았습니다.

서술 API와 검토 API는 기록에 없는 투척 준비 표현을 통과시켰습니다. 이 실측 실패를 근거로 코드 검사를 보강했고 해당 초안을 거부하여 확정 사건 기반 기본 서술로 대체했습니다. 거부된 초안과 이유는 감사용 JSON에 분리 보관합니다. [실제 생성 예시](trauma-example.md), [근거](trauma-example-evidence.json).

### 부상 지속 검증 — 통제된 응답

아래는 실제 API 출력이나 운영 사건이 아닙니다. 테스트가 두피 열상·출혈 1.5·시야 제약 0.4를 입력하고 실제 엔진을 진행시킨 결과입니다. [전체 상태·사건](trauma-controlled-evidence.json).

| 시점 | 출혈 강도 | 누적 출혈 부담 | 시야 제약 | 통증 |
|---|---:|---:|---:|---:|
| 00:05 공격 확정 | 1.500 | 0 | 40% | 4.00 |
| 00:35 경과 | 1.485 | 0.01538 | 40% | 3.83 |
| 00:40 의약품 처치 후 01:15 | 0 | 0.02033 | 0% | 3.42 |

처치로 출혈이 멎고 피에 의한 시야 제약이 해소되어도 누적 손실과 통증이 즉시 사라지지 않습니다. 다리의 구조적 기능 저하는 별도의 회복 경로를 따릅니다. 출혈이 있어도 시야 저하가 없는 제안 역시 허용합니다.

## 범위와 한계

수치·응고·회복·사망 한계는 허구 세계용 게임 모델이며 실제 의학 예측 모델이 아닙니다. 부상별 if 문 대신 공통 필드와 부위-기능 호환표·강도 상한을 사용합니다. 현재 공격 도구는 근접 접촉형이고, 한 공격당 복합 부상 한 묶음을 제안합니다. 내부 장기·감염·영구 장애·투척 탄도까지 모델링하지는 않습니다. 데모 모드는 비용 없는 기존 결정적 판정을 유지합니다.

AI 서술의 모든 의미 오류를 정규식이나 별도 AI 검토가 완벽하게 검출한다고 보장할 수는 없습니다. 코드 검증·근거 검토·실패 시 기본 서술을 함께 적용하며, 실제 확인된 오류는 회귀 테스트로 남깁니다. 조용한 단일 공격 사례를 장편으로 부풀리지 않았습니다.

운영 세계는 테스트로 진행시키지 않았습니다. 배포 전 상태는 기존 5명, DAY 1 12:00, PAUSED / WORLD_CONTEXT_TOO_LARGE, 기존 호출 36회입니다. 이번 변경은 이후 실제 실행 세계의 공격에 적용됩니다.

최종 배포: `05fad385-331f-4b46-991e-57dd3456e1dd` SUCCESS. 메인 페이지·현재 세계 API HTTP 200 확인. 배포 후에도 동일 시즌·5명·DAY 1 12:00·PAUSED·호출 36회를 확인했습니다.
