# 반복 구조 수정: 오프라인 검증

기존 작업 트리의 변경사항을 유지했다. 수정 전에 관련 파일을 `data/context-revision-before`에 별도 복사했다. 저장된 사건을 재생했으며 AI 제공자 API 호출과 운영 세계 테스트 틱은 0회다.

- `server/world/contextSelection.ts`, `knowledgeFilter.ts`, `server/domain/worldAgent.ts`: 관찰 권한을 먼저 적용하고 시간을 기준으로 최신순 선택한다. 직전 충돌, 자신의 부상, 실패, 상대의 실제 응답을 압축된 판단 근거로 보존한다. 자기 상태 변화의 부상 항목을 우선 보존한다. 다른 인물의 비공개 기억·메모·소지품은 제외한다. 입력 크기를 맞출 때 같은 사건의 중복 표현부터 제거한다.
- `server/world/motivations.ts`, `decisionController.ts`: 실제 관찰한 공격 결과와 실패를 평가한다. 반복 공격 비용, 부상·통증, 위험 감수, 공격성, 협상 성향이 공격·관찰·이동·협상·치료 점수에 영향을 준다. 공격적인 인물은 여전히 공격을 선택할 수 있다.
- `server/domain/sceneEvidence.ts`, `narrator.ts`, `storyComposition.ts`, `worldStore.ts`, `server/prompts/narratorPrompt.ts`, `novelNarration.ts`: 연결된 타격을 하나의 장면 단위로 묶는다. 프롬프트가 커져 분할할 때도 충돌을 쪼개지 않는다. 두 공격을 각 인물 문단으로 따로 시작하거나 앞선 경고를 공격 뒤에 배치한 DAY 출력은 거부한다. 과거 반격 연결 근거가 없으면 인지·반격을 확정하지 않는다. 기록에 없는 부상·목격자 생각은 추가하지 않는다.
- `storyComposition.ts`: 작은 통증·이동 제약 변화는 상태와 원본 사건 로그에 남기지만 LIVE/DAY 독립 장면은 만들지 않는다. 사망과 큰 출혈·통증·기능 저하 경계 통과는 이야기 후보로 남긴다.
- 기존 세계 시작 기록은 관계가 있다고 명시한다. `novelNarration.ts`가 이를 근거로 “기존 관계가 없었다”는 반대 진술을 거부한다.

검증: TypeScript, 전체 173개 테스트, 빌드와 공개 번들 비밀값 검사 통과. 저장된 DAY 1 04:05 두 공격은 공격 2회·피해 각 1·몸통 타박상·출혈 없음·기존 이동 제약을 보존했다. 재생 시 장면 단위는 충돌 1개와 김기업 탐색 1개였다. 오래된 사건을 앞에 쌓아도 최근 근거를 선택했고, 타인의 비공개 정보가 입력에서 제외됐다. 정지 시점의 마스킹된 운영 스냅샷으로 다섯 판단 요청 모두 20,000바이트 이하를 확인했다(19,605–19,991바이트). 이 오프라인 측정은 현재 운영 세계의 미래 입력까지 보증하지 않는다.
