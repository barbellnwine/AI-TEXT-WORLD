# 캐릭터 의사결정 개편 — 2026-09-25

## 원인과 변경

기존의 욕구별 행동 우선순위와 최근 행동 쿨다운만으로는 장기 목표, 성향, 실패 이후의 목표 상태를 표현할 수 없었다. 이번 변경은 그 위에 서버가 계산하고 검증하는 행동 후보와 지속적인 목표 기록을 추가한다. WORLD RULES → WORLD STATE → WORLD ENGINE → AGENTS → EVENT LOG → NARRATOR 순서는 유지한다.

1. **욕구**는 현재 자신의 허기·갈증·피로·위험·소속 부족이다.
2. **욕망과 목표**는 캐릭터의 장기 목표와 `SECURE_SUPPLIES`, `BUILD_TRUST`, `KEEP_RESERVE`, `LEAVE_DANGER`, `DEFEND_SELF` 등의 당면 목표로 구분한다. 목표별 시도·실패·근거 사건·행동 ID와 active/blocked/achieved/abandoned 상태를 저장한다.
3. **성향**은 자기중심성·공감·신뢰·경쟁심·위험 감수·공격성·협상 선호·충동성의 0–10 값이다. 매 판단마다 다시 추첨하지 않는다.
4. 서버가 자신의 상태, 현재 접촉 가능한 상대, 실제로 목격한 물건, 관계와 실패 이력으로 후보를 만든다. 이익 + 성향 적합성 + 관계 영향 + 목표 지속성에서 비용·위험·최근 실패 비용을 뺀 점수를 계산한다. 행동 가능 여부도 엔진으로 검사한다.
5. AGENT는 실제 후보 ID를 선택하거나 다른 합법적인 시도를 제안할 수 있다. 최고 점수를 강제하지 않으며 대기도 가능하다. 선택 ID로 대상·물건을 바꾸려 하면 서버가 원래 후보에 결합한다. 반복 행동의 대체 선택에도 평가된 후보를 사용한다.
6. 엔진과 규칙 판정 이후에만 행동을 시작하고, 완료 시 소유권·거리·몸 상태 등을 다시 검사한다. 실제 결과를 개인 기억과 목표에 연결한다. 상대가 거래를 수락하거나 거절한 결과도 원래 제안자의 목표에 반영한다.

## 추가 행동과 사실성

- `HIDE`: 가진 물건을 감춘다. 물건을 새로 만들지 않는다. 다른 인물이 자동으로 감춤이나 위치를 알지 않는다.
- `ROB`: 실제로 알고 있는 상대의 물건을 강탈하려 시도한다. 기존 전투 판정을 거치며 상대가 계속 저항할 수 있으면 물건을 얻지 못한다. 현재 MVP에서 실제 공격 후 부상 8 이상 또는 사망으로 저항 불능인 경우에만 이전한다.
- `STEAL`: 실제 목격·제안으로 알게 된 물건만 대상이 된다. 경계·피로·기회·은폐 여부에 따라 실패할 수 있다.
- 협력과 거래는 제안으로 시작한다. 상대의 수락·거절을 제안자가 대신 확정하지 않는다. 자원을 얻기 전에는 자원 확보 목표를 완료하지 않는다.
- 공격의 동기는 자원 욕심에 한정되지 않는다. 눈앞의 공격, 기존 적대 관계, 공개된 배틀로얄 경쟁 목표도 후보를 만든다. 주기적인 강제 전투는 없다.
- 다른 인물의 성향·사적 목표·미관측 소지품을 판단 입력에 노출하지 않는다. 공개 관전 API에서도 개인 목표·평가 기록을 제외한다.

## 관리자 사용법과 이전 데이터

- 세계 편집기 → **6. 캐릭터 생성 → 수정**에서 8가지 성향을 설정하고 초안을 저장한다.
- 이미 시작한 시즌은 **관리자 운영 화면 → 캐릭터의 지속적인 성향**에서 인물을 선택한다. 세계를 일시정지한 상태에서 저장하면 이후 판단에 적용된다. 이미 실행 중인 행동과 과거 사건은 바꾸지 않는다.
- 기존 DB에는 nullable `dispositions_json` 열만 추가한다. 이전 캐릭터는 중립 기본값 5로 읽으며 데이터나 이름을 삭제하지 않는다. 자동 생성 캐릭터는 이름·성격을 시드로 서로 다른 안정적인 기본값을 받고, 관리자가 수정할 수 있다. 이 값은 성격 문장을 의미 분석해 추출한 수치가 아니다.
- 목표와 성향은 체크포인트에 저장되므로 다음 DAY와 재시작에도 유지된다. 성향 변경은 운영자 기록에도 남는다.

## 실제 검증

운영 데이터 대신 메모리 SQLite와 모의 모델 응답을 사용했다. 실제 유료 모델 호출은 하지 않았다.

- 타입 검사, 프로덕션 빌드와 공개 번들 비밀정보 검사 통과.
- 전체 단위·통합 테스트 **135개 통과**. 이번 개편 전 122개에서 13개 추가했다.
- 데스크톱·모바일 Playwright **12개 통과**: 관리자 로그인, 성향 초안 저장, 운영 중인 시즌의 성향 저장·새로고침, LIVE/DAY, 조용한 틱, 미니맵 회귀 검사.
- 같은 식량 부족과 동일한 관측 정보에서 협력형은 `COOPERATE`, 협상형은 `SPEAK/NEGOTIATE`, 기회 추구형은 실제로 잠든 소지자를 향한 `STEAL`을 최고 평가했다. 이것은 **서버 평가 테스트 결과**이며 실제 OpenAI 모델이 항상 같은 행동을 선택한다는 뜻은 아니다.
- 실제 절도 완료 후에만 소유권·목표 완료·기억이 바뀌었다. 잠든 피해자에게 범인 정보가 자동 전달되지 않았다.
- 거래 제안만으로는 물건이 옮겨지지 않았다. 상대의 독립적인 수락 후 양방향 물건 이전·신뢰 변화·제안자의 목표 완료를 확인했다. 거절하면 이전 없이 목표가 blocked로 남았다.
- 강탈 실패와 저항 불능 상태에서의 실제 이전을 각각 검증했다. 실패 이력은 다음 평가에 남는다.
- 빈 탐색은 물건을 생성하지 않고 실패·목표를 남기며 다음 탐색 구역을 바꾼다.
- 다음 DAY에도 소유권·성향·목표·관계가 유지된다. 잘못된 별도 제안의 거절이 이전 목표를 실패 처리하지 않는다.
- 이미 달성한 목표를 나중에 다시 추구할 때는 별도 목표 기록을 만든다. 과거 달성을 덮어쓰지 않고 새 목표의 시도와 중단을 구분한다.
- 후보 ID를 선택하는 모의 AGENT → 규칙 판정 → 행동 완료 → 목표/평가 저장 → 체크포인트 복원 경로까지 검증했다.

## 서술과 남은 한계

이번 변경은 새 행동·목표·반응의 원인을 만들며 기존 EVENT LOG 기반 LIVE/DAY 서술 경로를 사용한다. NARRATOR에게 새 소유권·대사·전투·결말을 생성할 권한은 주지 않았다. 과거 스토리를 이 변경의 결과인 것처럼 다시 쓰지 않는다.

사람의 사고를 완전히 재현하는 모델은 아니다. 효용 가중치와 전투 결과는 MVP 규칙이며 장기 관찰로 조정해야 한다. 자유롭게 작성한 장기 목표의 의미 해석은 AGENT가 맡고, 목표의 실제 진척·실패·완료는 서버가 관리한다. 현재 지원하지 않는 건설·무기 효과나 물리 행동은 문장만으로 실행되지 않는다. 실제 모델과 장기간 진행했을 때의 문학적 완성도·행동 분포는 이번 무비용 검증으로 보장하지 않는다.
