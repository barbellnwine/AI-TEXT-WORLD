# 반복 출력 수정 보고

## 적용 범위와 원인

- AGENT 요청은 상세 사건의 `detail`·부상 JSON·같은 기억·사실을 중복 포함했다. `server/world/contextSelection.ts`, `server/domain/worldAgent.ts`에서 지식 필터 이후 현재 위협, 본인 관련 사건, 최근 기억과 장소를 선별하고 사건을 요약 필드로 전송한다. 현재 신체·부상과 규칙은 보존하며 전송 한도는 20,000바이트 그대로다. 원본 기록은 삭제하지 않는다.
- `server/world/motivations.ts`의 범용 공격 이유와 고정 몸통 후보를 목표·기억·관계 및 전술에 따른 후보로 바꿨다. 공격 중단을 노리는 팔 공격, 위험을 감수하는 머리 공격, 큰 표적을 노리는 몸통 공격의 이유를 구분하며 협상·회피도 후보에 남긴다. 무작위 부위 변경이 아니다.
- `server/world/physicalActions.ts`, `worldEngine.ts`, `engineTypes.ts`는 공격 시작과 인지된 대응을 구분한다. `responseToActionId`, `noticedEventId`, `exchange`를 기록한다. 상대가 이미 공격하고 있다는 사실만으로 반격이라 부르지 않는다. 목격자는 별도 선택을 하도록 깨우지만 고정 감정 문단을 생성하지 않는다.
- `server/domain/sceneEvidence.ts`, `narrator.ts`, `server/prompts/narratorPrompt.ts`는 연결된 타격을 충돌 그룹으로 전달하고 등장인물의 나이·소개·목표·자신의 관계·근거 기억을 제한적으로 포함한다. 과거의 연결 근거 없는 반격과 목격 템플릿은 **서술용 사본에서만** 제외한다. 저장 원본과 피해는 유지한다.
- `server/domain/novelNarration.ts`는 타박상→찰과상 변환, 근거 없는 반격, 일부 주어 혼동, 문장·문단 중복과 사건 누락을 코드로 검사한다. AI 검토와 별개로 적용하고 재작성은 1회만 허용한다. 실패하면 확정 사실 기반 서술을 사용한다.
- `server/world/trauma.ts`, `traumaAdjudication.ts`: 새 기능 저하는 상처별 `basis`가 필요하다. 통증 효과는 통증 정도에 비례한 상한으로 제한한다. 통증 2인 경상에 통증을 이유로 mobility 0.3을 다시 부여하면 거부한다. 기존 확정 부상 0.3은 소급 변경하지 않는다.
- `server/domain/modelTrace.ts`, `worldStore.ts`, `server/api/worldAdminRoutes.ts`: 호출 목적·모델·요청 바이트·시간·토큰·오류·대체 여부를 최대 200건 보존한다. 개발 환경에서 `AI_WORLD_CAPTURE_TRACE=true`일 때 비밀값을 지운 요청/응답/최종 출력도 보존한다. 관리자 진단 API는 읽기 전용이다.

## 환경물

현재 세계는 초안 물품 배열과 엔진 물품이 모두 0개였다. 장소 설명에도 돌·숲·모래의 구체적 근거가 없었다. 따라서 운영 세계에 임의로 물건을 넣지 않았다.

`server/domain/environmentItems.ts`와 `src/world/pages/admin/WorldStudioPage.tsx`에 **장소 묘사로 환경물 초안 추가** 버튼을 넣었다. 야외 장소의 실제 설명을 바탕으로 돌·나뭇가지·모래 초안을 만들고, 관리자가 수량과 구역을 검토해 저장한다. 새 세계 시작에 적용하며 과거 사건을 바꾸지 않는다. 이 초안 생성은 현재 제한된 재료 목록만 지원한다.

## 남은 한계 / 기록 정정

기존 API 요청·원본 응답은 과거에 저장하지 않아 복원할 수 없다. A의 수정 전 입력은 저장된 사건이며 과거 요청 그대로가 아니다. 새 사실 검사는 제한된 표현과 ID 근거를 검증하지만 한국어의 모든 의미 오류·간접적 중복을 증명하는 검증기는 아니다. 마지막 AI 본문에도 타격을 문단별로 따로 설명하는 경향과 메타 표현이 남아 있다. 소설 품질이 완전히 해결됐다고 보지 않는다.

기존 공개 챕터는 삭제하거나 덮어쓰지 않았다. 공개 기록을 정정하려면 원문을 유지하고 근거 ID와 수정 사유를 붙인 별도 정정본을 발행해야 한다. 이번 작업에서는 비교 파일만 만들었다. 운영 세계는 테스트용으로 진행하거나 재개하지 않았다.
