# AI WORLD 행동·서술 개편 (2026-09-24)

## 확인한 원인

1. `behaviorPolicy`는 허기/피로 7 이상이면 모든 대화를 막고, 같은 상대에게 하는 모든 말을 하나의 6시간 쿨다운으로 처리했다. 질문이나 거절도 막혔다. 대체 행동은 모든 인물에게 같은 순서였다.
2. 완료/실패 결과의 기억 저장이 일부 사건 유형에 한정됐다. 실패한 탐색 구역과 최근 판단을 다음 의사 결정에 구조적으로 전달하지 않았다.
3. 한 장소 안의 모든 인물이 서로 보이는 것으로 처리됐고, 협력은 상대의 별도 응답 없이 관계를 개선할 수 있었다. 교환 제안/거절 프로토콜이 없었다.
4. 신체 임계값 사건이 시간대별 장면에 들어갔고, TEXT도 LIVE의 시간대별 장면을 읽었다. 별도 DAY 구성기가 없었다.
5. 서술 AI는 올바른 사건 ID만 붙이면 자유로운 제목/본문을 저장할 수 있었다. 기존 종료/사망 단어 검사만으로는 발견이나 관계 변화를 검증할 수 없었다.
6. 일반 세계에서는 판정 AI의 `ended`가 실제 종료를 일으킬 수 있었다. 관리자 종료도 세계 안의 결말 사건을 만들었다. 호출 오류/예산 중지는 판단만 멈추고 시계는 계속 갔다.

이전 사진의 조기 종료는 예약 사건 '의문의 배틀로얄'의 실제 효과 `power_off`를 서술에서 게임 종료와 권력 해체로 잘못 해석한 사례였다. 당시 세계는 DAY 1 08:00 이후에도 진행했고 사망/세계 종료 사건은 없었다. 엔진의 전력 차단과 서술의 결말이 달랐다.

## 구현

- `decisionOptions.ts`, `behaviorPolicy.ts`: 본인의 필요·피로·젖음·두려움·야망·관계·실패 이력으로 후보 우선순위를 계산한다. 후보는 명령이 아니며 AI가 성격/직업/개인 목표와 함께 선택한다. 대체 행동도 후보 점수와 실패 구역에 따라 정렬한다. 실제 선택과 결과는 체크포인트에 저장한다.
- `interactions.ts`, `actionSchema.ts`, `worldEngine.ts`: 같은 장소/구역 접촉 검사, 목적별 대화, 제안 ID에 연결된 독립 응답, 거절, 동의 후 재검증하는 원자적 물건 교환. 제안만으로 소유권이나 상대 동의를 만들지 않는다. 절도는 이전에 상대가 직접 제시한 실제 물건만 대상으로 하며 경계/피로/거리/소유권을 검사한다. OBSERVE는 경계 행동으로 방어에 영향을 준다.
- `knowledgeFilter.ts`, `agentPrompt.ts`: 실제 접촉 가능한 상대, 관찰 가능한 공격 시도만 전달한다. 다른 사람의 소지품·사적인 기억·내부 결정은 공개하지 않는다.
- `worldStore.ts`: 공격 대상에게 최대 한 번의 독립 반응 슬롯을 추가한다. 예산 검사를 똑같이 적용하고 응답 대기 중에는 시계가 공격을 먼저 완료하지 않는다. 잠든 사람이나 이미 다른 일을 하는 사람을 무조건 방어시키지 않는다.
- `storyComposition.ts`: 상태 기록은 그대로 보관하고 LIVE에 의미 있는 결과만 통과시킨다. DAY는 전체 사건 저널에서 주요 인물과 상호작용을 선택하고 장소·시간·관련 사건으로 장면을 묶는다. 새로운 사건이 많으면 더 길어지고 조용한 날에는 상태 문장으로 분량을 채우지 않는다.
- `narrator.ts`, `narratorPrompt.ts`: 실제 발언만 인용한다. 서술 모델의 자유 본문은 받지 않고 사건 ID를 문단으로 묶는 편집 결과만 검증하여 렌더링한다. 모르는 물건이나 결말을 추가한 모델 출력은 저장되지 않는다. 모델 장애/비용 부족 시에도 동일한 근거 기반 렌더러를 사용한다.
- `/api/world/days`, `ChronicleReader.tsx`: TEXT는 DAY 단위 장을 읽고 LIVE는 실시간 결과를 읽는다. 현재 DAY는 진행 중이라고 표시한다. 연대기 API도 DAY 단위로 제공한다.
- 종료는 구조화된 엔진 조건/세계 시간 제한/생존자 상태로만 판정한다. 판정 AI의 `ended`는 권한이 없다. 종료 사유·시각·생존자·관련 사건을 저장하고 이후 직접 엔진 호출도 진행하지 않는다. 관리자 중지와 예산/연결 오류는 PAUSED다.
- `SceneEntry.tsx`: 정정한 글의 이전 제목/본문/시각/사유를 보존하여 펼쳐 볼 수 있다. 과거 장면의 사실 근거 사건은 삭제하지 않는다.

## 검증

운영 DB와 실제 모델을 사용하지 않은 테스트: 122개 통과. 타입 검사/프로덕션 빌드/공개 번들 비밀 검사 통과. 모바일·데스크톱 LIVE, 상태 문장 미발행, GPS 미니맵 검증 통과. TEXT/DAY/정정 내역까지 포함하여 모바일·데스크톱 UI 8개 시나리오를 통과했다.

추가 검증에는 열 명의 실제 환경 노출 상태와 감사 기록 유지, 서로 다른 필요에 따른 후보 순위, 구역 밖 접촉 금지, 높은 피로에서도 거절 허용, 본인이 아닌 사람의 수락 위조 금지, 교환 완료 전 소유권 변경 시 취소, 절도 대상 지식 제한, 실패 이력 복원, 공격 대상의 독립 방어, 허위 서술/중복 근거 거부, 엔진 종료와 관리자 중지 구분이 포함된다.

`world-story-test-example.md`는 테스트가 실제 엔진에 행동을 넣고 얻은 사건/발언/상태 변경으로 생성했다. 운영 세계 결과가 아니다. 재생성: PowerShell에서 `$env:WORLD_EXPORT_EXAMPLE='1'` 후 `npm test`, 이후 해당 환경 변수를 제거한다.

## 배포 및 운영 확인

Railway 메인 사이트에 반영했다. 읽기 전용 확인 시 DAY 1 19:00, 생존자 5명, PAUSED였고 새 DAY API는 실제 근거 8개로 진행 중인 DAY 장을 반환했다. 재개·리셋·유료 테스트 호출은 하지 않았다.

## 한계 및 운영 확인

- 이번 검증은 실제 유료 모델이 장시간 얼마나 흥미로운 선택을 하는지 측정하는 품질 평가가 아니다. 실제 전투/대화 발생 빈도는 성격·자원·규칙·현재 위치와 모델 선택에 달려 있다. 승자나 죽음을 연출하지 않는다.
- 현재 서술은 사실 보장을 위해 근거 문장의 구성과 실제 대화를 사용한다. 자유로운 소설 문장을 생성하고 모든 의미를 자동 증명하는 시스템은 아니다. 선택 동기는 AGENT가 기록한 의도이며 객관적 성공 결과와 구분해서 읽어야 한다.
- 지도 구역은 실제 물리 거리의 연속 시뮬레이션이 아닌 기존 `localArea` 단위다. 절도는 관찰된 제안 물건에 한정한다. 새 자원 생성·불 피우기·건설·무기 효과는 구현하지 않은 능력으로 남는다.
- 기존 설정의 전원이 꺼지는 예약 사건 자체는 삭제/변경하지 않았다. 운영 시뮬레이션도 재개/리셋하지 않는다.
- 이미 이전 버전이 덮어쓴 잘못된 본문 전체는 원문 저장소가 없어 소급 복원할 수 없다. 첨부 화면과 당시 근거를 정정 사유로 남기되 원문을 추정해서 복구하지 않는다. 이번 버전 이후 자동 정정에는 원문 이력이 남는다.
- 자유 텍스트 종료 조건만 있고 구조화된 조건이 없는 옛 설정은 AI가 임의로 판정하지 않는다. 관리자에서 DAY/생존자/목표 등 지원하는 종료 조건을 지정해야 한다.
